# Building and testing

How to build and test the repository, and how its demo pictures are kept up to date.

## Build and test

```sh
dotnet build SharpCompute.slnx
dotnet test SharpCompute.slnx
```

The samples, the tests and the benchmarks precompile their shaders when the Xcode Metal Toolchain is
installed, and compile them at run time when it is not; the tests that need a precompiled library
are then skipped. `-p:SharpComputePrecompileShaders=false` builds and tests everything without
precompiled shaders. See [Precompiled shaders](precompiled-shaders.md).

## Generated sources

The vector, matrix and intrinsic sources are generated by `tools/gen_vectors.py`.
`python3 -I tools/gen_vectors.py --check` verifies they're up to date.

## Demo pictures

Every picture in the README is the demo's own deterministic headless output.

- A new or changed demo regenerates its screenshots and their thumbnails with
  `scripts/make-screenshots.sh <demo>`, and its animation, if it has one, with
  `scripts/make-gifs.sh <name>`.
- A new demo is added to the [Demos](../README.md#demos) grid: a new ComputeLab page is a cell of
  [ComputeLab pages](../README.md#computelab-pages), a new demo a cell of the grid and a
  `demo_<name>` function in the script.
- The grids show the thumbnails in `docs/screenshots/thumbs/`, each linking to its full image.
- The tests (`dotnet test --filter ReadmeImage`) check that every image the README shows exists, has
  alt text, is opaque and stays within its limit: 400,000 bytes for a screenshot, 100,000 for a
  thumbnail and 2,000,000 for a GIF (the limits in `scripts/_common.sh`). They also check that every
  image and relative link in the README and in `docs/` resolves.
